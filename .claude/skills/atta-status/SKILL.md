# 项目状态评估

> **本阶段目标：** 建立项目当前状态的全面快照。对照 CLAUDE.md 的项目结构声明、docs/ 中的设计文档，审计实际代码库，发现差异与问题。

## 流程

### 1. 对照 CLAUDE.md 项目结构

对比 CLAUDE.md 中声明的目录结构与实际文件系统：
- 声明的目录是否存在？路径是否匹配？
- 存在的目录/文件是否未被文档覆盖？
- `src/main/`、`src/preload/`、`src/renderer/` 各子目录是否与声明一致？

### 2. 对照 docs/ 设计文档

- 列出 `docs/` 下所有设计文档
- 每个设计文档描述的组件/模块哪些已实现、哪些缺失？
- 是否存在已实现但无设计文档覆盖的模块？

### 3. 代码库健康检查

- **package.json** — 依赖是否有已知漏洞？是否有多余依赖？
- **TypeScript** — 是否有 `tsconfig` 配置问题？
- **测试覆盖** — `test/` 目录结构，是否存在对应测试文件？
- **死代码** — 是否有未被引用的文件/导出？（不删除，只报告）

### 4. 架构一致性

对照 CLAUDE.md 声明的技术栈和架构模式：
- contextBridge API 暴露是否符合最小化原则？
- 主进程/预加载/渲染进程的职责分离是否清晰？
- IPC 通道命名是否一致？

### 5. 状态评级

对每个维度给出状态：

| 状态 | 含义 |
|------|------|
| ✅ Healthy | 一致，无问题 |
| ⚠️ Gap | 有差异但不阻塞 |
| ❌ Broken | 严重不一致，需立即修复 |
| ❓ Unknown | 无法判断，需深入 |

## 铁律

- **只读不写** — 不修改任何文件，不"顺手修"发现的问题。
- **不猜测** — 无法确定的事项标记为 ❓ 而非硬给结论。
- **全面但非穷举** — 覆盖所有主要模块，但不对每个文件逐行审计。
- **列出问题并标注影响** — 每个差异标注严重程度（阻塞/重要/轻微），但不分配具体执行人。
