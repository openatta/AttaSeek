# 重构优化

> **本阶段目标：** 在保持特性与功能完全不变的前提下，优化软件的非功能质量属性——架构、代码结构、API 合理性、错误处理、死代码清除。不新增功能，不修复业务 bug。

## 何时用

| 场景 | 用哪个 |
|------|--------|
| 优化代码结构、消除技术债、提升可维护性 | `/atta-refactor` ← 这个 |
| 新增功能 | `/atta-feature-dev` 或完整特性 track |
| 修复 bug | `/atta-bug-fix` 或完整修复 track |
| 了解当前代码质量概况 | `/atta-status` |

## 流程

### 阶段 1: 分析与简报（只读，不改代码）

按七个维度审查代码库：

**1. 架构与分层**
- 主进程 / 预加载 / 渲染进程的职责分离是否清晰？
- 依赖方向是否正确（renderer 不直接依赖 main，preload 是唯一通道）？
- 是否存在跨层泄露（如 main 的类型直接 import 到 renderer）？

**2. 代码结构**
- 文件组织是否符合项目结构约定（CLAUDE.md）？
- 模块内聚性：一个模块是否承担了过多职责？
- 是否存在循环依赖？
- 是否存在过长函数（>50 行）、过大文件（>300 行）、过深嵌套（>4 层）？

**3. API / 接口合理性**
- IPC channel 命名是否一致？是否有未使用的 channel？
- 函数签名是否清晰（参数数量、可选参数位置、返回值类型）？
- 类型定义是否准确（避免 `any`、正确的 `null`/`undefined` 语义）？
- contextBridge 暴露的 API 是否符合最小化原则？

**4. 重复与死代码**
- 是否存在复制粘贴的代码块（>5 行相同逻辑）？
- 是否存在未使用的导入、函数、变量、文件？
- 是否存在注释掉的代码块？

**5. 错误与异常处理**
- 错误处理模式是否一致（try/catch、error propagation、error types）？
- 异常是否正确传播到调用方？
- 错误信息是否有意义（包含上下文，不是 "error" / "failed"）？
- IPC 错误是否在两端都得到处理？

**6. 命名与可读性**
- 变量、函数、类型命名是否清晰、意图明确？
- 注释是否与代码一致（是否过时或误导）？
- 是否存在魔术数字或魔术字符串？

**7. 性能与资源**
- 是否存在不必要的重渲染（React）、重复计算、重复 I/O？
- 是否存在同步阻塞（主进程或渲染线程）？
- 是否存在内存泄漏风险（未清理的监听器、定时器、ref）？

### 阶段 2: 决策门

阶段 1 完成后，输出以下简报，**等待用户明确同意**后再进入阶段 3：


### 阶段 3: 实施与回归（用户确认后）

对每个重构项执行：

```
1. 理解 → 读相关代码，确认影响范围
2. 重构 → 仅改当前项，保持外部行为完全不变
3. 回归 → typecheck + test + build 必须全部通过
4. 等价 → 对比重构前后的测试结果，确认无行为变化
5. 下一个 →
```

**每个重构项完成后项目必须可构建、测试全通过。** 如果某个重构导致测试失败，立即回滚该项并记录原因。

全部完成后输出重构完成简报：

```markdown
## 重构完成简报

### 执行情况
- 计划项: N | 已完成: N | 跳过: N

### 变更清单
- `path/file.ts` — 重构内容（一行说明，标注对应清单编号）

### 回归结果
| 检查项 | 结果 |
|--------|------|
| `npx vitest run` | ✅ N passed / ❌ M failed |
| typecheck | ✅ / ❌ |
| `npm run build` | ✅ / ❌ |

### 改善总结
| 重构前 | 重构后 |
|--------|--------|
| [问题描述] | [改善效果] |

### 遗留建议（未执行的重构机会）
- [ ] ...（低优先级，可在后续单独处理）
```

## 铁律

- **不新增功能** — 重构只改结构，不改行为。发现缺少的功能记录为建议，不做。
- **不修业务 bug** — 重构中发现 bug 记录并询问用户，不顺手修。避免重构与修 bug 混合导致回归难以定位。
- **每次重构可回归** — 每个重构项完成后 typecheck + test + build 必须全通过，否则回滚该项。
- **先分析后动手** — 必须等用户确认简报后才能进入阶段 3。
- **高风险项拆小** — 高风险重构拆成更小步骤（每个步骤单独回归），降低回滚成本。
- **保持等价** — 重构前后的测试结果必须一致。测试通过数减少 = 行为变化 = 不是纯重构。
