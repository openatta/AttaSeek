## 关键模块设计

### 1. Prompt Cache 共享（`cache/`）

```
CacheManager
  ├─ cacheMap: Map<string, CacheEntry>
  ├─ createCache(params: CacheSafeParams): string  → 生成 cache key
  ├─ getCache(key: string): CacheEntry | undefined
  ├─ invalidate(key: string): void
  └─ cleanup(): void  → BrowserWindow close 时调用

CacheSafeParams
  ├─ systemPromptStatic: string    → 静态系统提示词部分
  ├─ tools: LLMToolDef[]           → 工具定义
  ├─ modelConfig: ModelConfig      → 模型配置
  └─ profileId: string             → profile 标识

LLMMessage 扩展:
  content 中的 block 新增可选字段:
    cache_control?: { type: 'ephemeral' }
  在静态系统提示词最后一个 block 和工具定义最后一个 block 标记断点
```

**数据流：** 父 Agent 构建 `CacheSafeParams` → `CacheManager.createCache()` → 子 Agent fork 时 `CacheManager.getCache()` → 在 LLM 请求中注入 `cache_control` 断点 → Anthropic API 返回 `cache_creation_input_tokens` / `cache_read_input_tokens`

### 2. 流式工具执行（`orchestration/StreamingToolRunner`）

```
StreamingToolRunner
  LLM 流式响应中:
    onContentBlockStart(block) → 如果是 tool_use → 创建待执行条目
    onContentBlockDelta(delta)  → 累积 input_json
    onContentBlockStop(block)   → 完整的 tool_use 就绪 → 立即加入执行队列
    onMessageStop()             → 等待所有工具完成 → 收集结果

  执行队列:
    reads:  → 并行执行 (maxParallelTools)
    writes: → 顺序执行 (逐个)
    结果:   → 注入下轮 LLM 请求的 tool_result 块
```

### 3. Post-Sampling Hooks（`hooks/`）

```typescript
// Hook 类型
interface PostSamplingHook {
  name: string
  priority: number
  condition: (ctx: HookContext) => boolean  // 触发条件: 每turn / 首次 / 每N轮
  execute: (ctx: HookContext) => Promise<HookResult>
}

interface HookResult {
  messages?: LLMMessage[]           // 注入下一轮的消息
  preventContinuation?: boolean     // 阻止继续
  blocking?: string                 // 阻塞原因
}

// Hook 管道
HookManager.executeHooks(ctx):
  for hook of sortedHooks:          // 按 priority 排序
    if hook.condition(ctx):
      result = await hook.execute()
      if result.preventContinuation → 停止管道
      ctx.messages.push(...result.messages)
```

**内置 hooks：**

| Hook | Priority | 触发条件 | 功能 |
|------|----------|---------|------|
| `confidence` | 10 | 每 turn | 检测模糊词比例 → 低于阈值时生成 coaching |
| `coaching` | 20 | confidenceHook 触发后 | 生成具体改进建议注入下轮 prompt |
| `brief` | 30 | 每 turn | 生成简短后续建议（≤50 字） |
| `memory` | 40 | 每 turn | 同现有 MemoryExtractor，迁移到 hook 中 |

### 4. Skills 运行时（`skills/`）

```
SkillLoader
  ├─ loadFromDir(baseDir: string): SkillManifest[]
  │    扫描 .claude/skills/*/SKILL.md
  │    解析 YAML frontmatter (name, description, tools, layer, …)
  │    Markdown 正文即为 skill 指令内容
  ├─ loadFromPackage(pkg: SkillPackage): SkillManifest[]
  └─ watch(dir): 文件变更检测 + 热重载

SkillExecutor
  ├─ injectPrompt(skill: SkillManifest): string
  │    将 skill 指令注入系统提示词 "Loaded Skills" 段
  │    LLM 根据指令内容自主决策何时激活
  └─ skill 执行完全由 LLM 驱动（无预定义步骤序列）
```

**Skills marketplace 包格式（`.skill` / tar.gz）：**

### 5. 工具体系扩展

**新增工具一览：**

| 工具 ID | 分类 | 风险 | 实现要点 |
|---------|------|------|---------|
| `write_file` | 文件 | write | `fs.writeFileSync` + 路径沙箱 + 原子写入（临时文件→rename） |
| `edit_file` | 文件 | write | 精确字符串替换（`file.replace(oldStr, newStr)`），失败报告 |

| `task_update` | 任务 | write | 更新任务状态/描述 |
| `task_list` | 任务 | read | 列出当前 session 所有任务 |
| `task_output` | 任务 | read | 获取子任务输出 |
| `push_notification` | 通知 | write | Electron `Notification` API |
| `lsp_diagnostic` | LSP | read | 通过 LSP server 获取文件诊断 |
| `lsp_definition` | LSP | read | 跳转到符号定义 |
| `lsp_references` | LSP | read | 查找符号引用 |
| `web_fetch` | 网络 | read | 已有实现，注册即可 |

### 6. MCP 集成（`mcp/`）

```
MCPServerManager
  ├─ servers: Map<string, MCPProcess>
  ├─ startServer(config: MCPServerConfig): Promise<void>
  │    spawn 独立子进程（cmd + args + env）
  │    stdio 通信（JSON-RPC 2.0 over stdin/stdout）
  │    初始化握手（initialize → initialized）
  ├─ healthCheck(serverId): Promise<boolean>
  │    定期 ping（默认 30s 间隔）
  │    崩溃自动重启（最多 3 次，指数退避）
  │    3 次失败 → 标记 unhealthy + 通知用户
  └─ stopServer(serverId): Promise<void>

MCPToolDiscovery
  ├─ discoverTools(serverId): ToolManifest[]
  │    调用 tools/list → 映射到 ToolManifest 格式
  │    注册到 ToolRegistry（标记 source: 'mcp'）
  └─ onServerCrash → ToolRegistry.unregisterBySource('mcp:' + serverId)

MCPResourceAccess
  └─ readResource(serverId, uri): Promise<{ contents: [] }>

MCPPromptProvider
  └─ getPrompt(serverId, name, args): Promise<{ messages: [] }>
```

### 7. Coordinator 多 Agent 模式（`coordinator/`）

```
CoordinatorMode
  Leader Agent:
    ├─ 接收用户复杂任务
    ├─ TaskDecomposer.decompose(goal, context):
    │    调用 LLM 分析任务 → 生成子任务列表（Task[]）
    │    每个子任务: { title, goal, profile, tools, dependsOn[] }
    ├─ fork Worker Agents (SubAgentManager.fork)
    ├─ 监控 Worker 进度 (SubAgentManager.list)
    └─ ResultSynthesizer.synthesize(results):
          收集 Worker 输出 → 调用 LLM 合成 → 生成 artifact

  WorkflowEngine:
    ├─ pipeline(items, ...stages): Promise<Result[]>
    │    每个 item 独立通过所有 stage（无 stage 间屏障）
    ├─ parallel(thunks): Promise<Result[]>
    │    屏障：等待所有 thunk 完成
    └─ phase(title): 进度标记（UI 展示用）

  Worker Agent:
    └─ 标准 SubAgentManager.fork() → 独立 AgentOrchestrator
       接收 Leader 分配的子任务 → 执行 → 返回结果
```

### 8. Worktree 隔离（`subagent/worktree/`）

```
WorktreeManager
  ├─ create(baseBranch: string): { path: string; cleanup: () => void }
  │    git worktree add <tmpdir> <baseBranch>
  │    注册到活跃 worktree 列表
  ├─ merge(path: string, message: string): boolean
  │    git add . && git commit && git checkout main && git merge
  ├─ discard(path: string): void
  │    git worktree remove --force <path>
  └─ cleanupOrphans(): void
       启动时执行 git worktree prune + 清理残留目录
```

## 数据流

### Prompt Cache 流程

```
主 Agent 首次 LLM 调用:
  systemPrompt = [static...] + DYNAMIC_BOUNDARY + [dynamic...]
  tools = [{cache_control: ephemeral}, ...]
  → Anthropic API 缓存 static + tools

子 Agent fork:
  CacheSafeParams { systemPromptStatic, tools, modelConfig, profileId }
  → CacheManager.createCache() → cacheKey
  → 子 Agent LLM 请求携带相同 static + tools
  → Anthropic API cache hit → cache_read_input_tokens
```

### Stream + Hook 完整管线

```
AgentOrchestrator.submitMessage():
  while (turnCount < maxTurns):
    1. ContextAssembly
    2. ContextManagement (compact)
    3. LLMCall:
         provider.chatStream(params, streamingCallback)
           streamingCallback:
             on text_delta → emit AgentMessageChunk
             on tool_use_block_complete → StreamingToolRunner.enqueue(toolUse)
         await StreamingToolRunner.waitAll()
         → 收集 toolResults
    4. HookManager.executeHooks(hookContext):
         confidence → coaching → brief → memory
         → injectHookMessages(nextState.messages)
    5. PostTurn (turnCount++, abort check)
```

## 技术决策

| 决策 | 选择 | 理由 | 替代方案 |
|------|------|------|---------|
| Cache 断点粒度 | 系统提示词静态部分 + 工具定义末尾 | Claude Code 的 `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` 模式。静态前缀和工具定义是跨 Agent 复用的最大 token 来源 | 全量 cache（但动态会话信息每次变化，缓存命中率低） |
| MCP 进程模型 | 独立子进程 + stdio JSON-RPC | MCP 协议标准传输方式。独立进程崩溃不影响主进程；stdio 比 HTTP 更轻量 | HTTP/SSE（需要端口管理、额外网络栈开销） |
| Skills 执行模型 | LLM 动态决策（非预定义步骤） | Claude Code 模式——LLM 根据技能 Markdown 指令自主选择工具。灵活、可扩展 | 预定义步骤序列（僵化，无法适应不同场景） |
| Coordinator 通信 | 单向 Leader→Worker 任务分配 + Worker→Leader 结果汇报 | 避免 Worker 间通信复杂度。Claude Code 的 `coordinatorMode` 也是 Leader-driven | 全对等通信（调试困难，收敛慢） |
| Worktree 合并策略 | 用户选择 merge/discard | Claude Code 的 `ExitWorktree` 接受 `action: keep|remove` 参数。安全优先——不自动合并 | 自动合并（可能引入破坏性变更） |
| `.skill` 包格式 | tar.gz + manifest.json | 标准化格式，包含元数据和内容。压缩传输效率高。可以包含二进制依赖 | npm 包（需要 Node.js 模块解析，太重）；纯文件夹（传输不便） |
| Bash 白名单 | 正则模式匹配（黑名单：rm/rmdir/chmod/chown/sudo） | 简单可靠。禁止破坏性操作但不限制开发工作流 | 命令白名单（太严格，npm/git 等工具的子命令难以枚举） |
| Hook 管道顺序 | Priority 排序，同步执行 | Claude Code 也是顺序执行。后续 hook 可使用前序 hook 的输出。confidence → coaching → brief 有依赖关系 | 并行执行（依赖关系被破坏） |
| 跨会话 cache 失效 | BrowserWindow close 时全量清理 | 简单，避免过期 cache 残留。`CacheManager.cleanup()` 在 `window-all-closed` 事件中触发 | TTL 自动过期（增加复杂度，但可能丢失有效的 cache） |
