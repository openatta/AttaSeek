### 1. 同步 I/O → 异步化 (P1 + P5)

```
src/main/agent/
├── memory/
│   └── FileMemory.ts              [修改] fs.*Sync → fs.promises.* + async 函数签名
├── skills/

    └── token-counter.ts           [不变] 纯计算，无 I/O
```

| 模块 | 操作 | 当前 | 改为 |
|------|------|------|------|
| `FileMemory.loadFileMemories()` | 读取 CLAUDE.md + .attaseek/memory/*.md | `readFileSync` x N | `await Promise.all(files.map(fs.promises.readFile))` |
| `SkillLoader.loadSkillsFromDir()` | 扫描 .claude/skills/*/SKILL.md | `readdirSync` + `readFileSync` | `await fs.promises.readdir` + `await Promise.all(files.map(readFile))` |

| `file-ops.grepImpl` | 递归目录 + 逐行搜索 | `readFileSync` 逐文件 | 异步批次 `await Promise.all(batch.map(search))` + 1000 上限 |

| 函数 | 调用方 | 影响 |
|------|--------|------|

| `loadSkillsFromDir()` | `boot.ts` | `boot()` 目前是同步函数，需改为 `async function boot()` 或使用 `.then()` |
| `globImpl.execute()` | `ToolExecutor.execute()` | `ToolExecutor.execute()` 已为 async，无影响 |
| `grepImpl.execute()` | 同上 | 同上 |

### 2. 提示词系统统一 (A5)

**问题：** 两套系统并存 — `PromptTemplate`（声明式 section 引擎，被 `AgentOrchestrator` 使用）和 `ContextBuilder` 的 `BASE_SYSTEM_PROMPT`（硬编码字符串拼接）。`AgentOrchestrator` 已修复为在 `contextBuilder.build()` 之后调用 `renderPrompt()`，但 `ContextBuilder` 内部的 `BASE_SYSTEM_PROMPT` 字符串仍然存在且未被使用。

**设计：** 将 `BASE_SYSTEM_PROMPT` 迁移为 `PromptTemplate` 的一个 section。

```
src/main/agent/
├── prompt/sections/
│   └── base-system.ts             [新建] 原 ContextBuilder 的 BASE_SYSTEM_PROMPT 移入
├── ContextBuilder.ts              [修改] 删除 BASE_SYSTEM_PROMPT 常量；删除 getRelevantSkillPrompts/getMemoryContext 的内联提示词拼接
│                                       ContextBuilder 变为纯数据获取器（messages + tools + memoryContext）
└── profile/profiles/*.ts          [修改] 所有 profile 的 systemPrompt.sections 追加 baseSystemSection
```

**迁移映射：**

| 原位置 | 内容 | 迁移目标 |
|--------|------|---------|
| `ContextBuilder.ts:100-112` | `BASE_SYSTEM_PROMPT` ("You are AttaSeek, an AI agent workbench assistant...") | `prompt/sections/base-system.ts` 的 `baseSystemSection` |
| `ContextBuilder.ts:126-137` | `getRelevantSkillPrompts()` 的 Markdown 渲染 | `prompt/sections/session-info.ts` 的 `condition` 中动态加载 |
| `ContextBuilder.ts:207-217` | `getMemoryContext()` 的文本拼接 | `prompt/sections/memory-context.ts` — 已有，需确保 promptCtx.memories 被填充 |

**数据流（统一后）：**

```
AgentOrchestrator.submitMessage():
  ctx = await contextBuilder.build(goal, sessionId, projectId)
       → 返回 { messages, tools, memoryEntries, skillEntries, artifactSummaries }
  promptCtx = { ...ctx, profile, sessionId, projectId, date, goal }
  state.systemPrompt = renderPrompt(profile.systemPrompt, promptCtx)
       → 按 priority 组装所有 sections（base-system → tools-usage → memory-context → session-info → ...）
```

### 3. Coordinator 集成 (A7)

**问题：** `CoordinatorMode.execute()` 返回的 `allEvents` 始终为空数组，子 Agent 进度对调用方不可见。

**设计：** 子 Agent 事件通过 `AgentEventBus` 转发，父 Agent 通过订阅接收。

```
AgentOrchestrator (parent)
  │
  │  LLM 返回 agent tool_use
  ▼
CoordinatorMode.execute(task, subtasks, profiles)
  │
  ├─ 1. 为每个 subtask fork 子 Agent (SubAgentManager.fork)
  │     │
  │     │  子 AgentOrchestrator.submitMessage()
  │     │    → yield 事件 → agentEventBus.emit(event)
  │     │                    ↑ 事件带有 agentId = subagent_{id}
  │     ▼
  ├─ 2. 父 Agent 通过 agentEventBus.subscribe('*') 接收子 Agent 事件
  │     → 检查 event.agentId → 匹配已知子 Agent → 转发到父事件流
  │
  ├─ 3. 所有子 Agent 完成后
  │     → ResultSynthesizer.synthesize(results)
  │     → 生成合成 artifact
  │
  └─ 4. 父 Agent 继续执行（子 Agent 结果作为 tool_result 注入消息历史）
```

**修改范围：**

| 文件 | 改动 |
|------|------|
| `coordinator/CoordinatorMode.ts` | `execute()` 改为 async generator，yield 子 Agent 事件（带 `sourceAgentId` 标记） |
| `shared/types/SessionEvent.ts` | `SessionEvent` 新增可选字段 `sourceAgentId?: string` |
| `orchestrator/AgentOrchestrator.ts` | 检测 `tool_use.name === 'agent'` → 调用 `coordinatorMode.execute()` → yield 子事件 |

### 4. WorktreeManager 集成 (A8)

**问题：** `SubAgentManager.fork()` 的 `context.isolation: 'worktree'` 路径从未被实现。

**设计：** 在 `SubAgentManager.fork()` 中添加 worktree 分支。

```
SubAgentManager.fork(parentTask, profile, goal, context)
  │
  ├─ if (context.isolation === 'worktree'):
  │     worktreePath = worktreeManager.create(agentId, baseBranch)
  │     task.projectId = worktreePath  // 子 Agent 工作目录指向 worktree
  │     // 子 Agent 完成后:
  │     onComplete: worktreeManager.merge(agentId, message) 或 discard(agentId)
  │
  └─ else (isolation === 'inline'):
        task.projectId = parentTask.projectId  // 共享工作目录
```

**修改范围：**

| 文件 | 改动 |
|------|------|
| `subagent/SubAgentManager.ts` | `fork()` 中添加 `if (context.isolation === 'worktree')` 分支 |
| `subagent/worktree/WorktreeManager.ts` | 已有完整实现，无需修改 |
| `subagent/SubAgentContext.ts` | 不变 |

### 5. CacheManager 驱逐策略 (P2)

**问题：** `CacheManager.cache` Map 无上限、无 TTL、无 LRU 驱逐。

**设计：** 添加简单的容量 + TTL 驱逐。

```
CacheManager
  maxEntries = 50             // 最多 50 个缓存条目
  ttlMs = 30 * 60 * 1000     // 30 分钟 TTL

  createCache(params):
    if (cache.size >= maxEntries):
      evictOldest()           // 驱逐最旧的条目
    key = cacheKey(params)
    cache.set(key, { ...params, createdAt: Date.now() })

  getCache(key):
    entry = cache.get(key)
    if (!entry) return undefined
    if (Date.now() - entry.createdAt > ttlMs):
      cache.delete(key)
      return undefined
    return entry
```

**修改范围：**

| 文件 | 改动 |
|------|------|
| `cache/CacheManager.ts` | 添加 `maxEntries`/`ttlMs` 常量 + `evictOldest()` |

### 6. task-mgmt 状态清理 (Q2)

**问题：** `task-mgmt.ts` 的 `taskStore` 是模块级可变数组，永不清理。

**设计：** 添加 `cleanupTaskStore()` 函数 + 在 `window-all-closed` 时调用。

```
task-mgmt.ts:
  export function cleanupTaskStore(): void { taskStore = [] }

boot.ts 或 index.ts:
  // 在 window-all-closed 事件中调用
  cleanupTaskStore()
```

**修改范围：**

| 文件 | 改动 |
|------|------|
| `tools/implementations/task-mgmt.ts` | 新增 `cleanupTaskStore()` |
| `main/index.ts` | `window-all-closed` 事件中调用 |

## 技术决策

| 决策 | 选择 | 理由 | 替代方案 |
|------|------|------|---------|
| I/O 异步化范围 | 仅 4 个热点函数 | FileMemory/SkillLoader/glob/grep 是唯一在请求路径上的同步 I/O。其他 I/O 在启动路径（boot.ts）可保持同步 | 全量异步（改动面过大，启动路径收益小） |
| 提示词统一方式 | 迁移 BASE_SYSTEM_PROMPT 为 section | 不新增抽象，复用现有 PromptTemplate 引擎。ContextBuilder 变为纯数据获取器，职责更清晰 | 保留两套系统（维护负担）；删除 PromptTemplate 退回字符串拼接（丧失声明式能力） |
| Coordinator 事件转发 | 通过 AgentEventBus 转发 | 复用现有 event 基础设施。子 Agent 事件自然流入父 Agent 的 MessageFlow。`sourceAgentId` 字段最小侵入 | 在 CoordinatorMode 内部通过回调转发（增加耦合） |
| Worktree 集成时机 | SubAgentManager.fork() 内判断 | 所有子 Agent 创建走同一入口，`isolation` 参数决定行为。调用方无需感知实现细节 | 在 CoordinatorMode 中单独处理（逻辑分散） |
| Cache 驱逐策略 | 容量上限 50 + TTL 30min | 简单有效。同任务内父子 Agent 通常 <10 个，50 上限充裕。30min TTL 覆盖典型会话时长 | LRU（更精确但复杂度高）；无驱逐（当前 bug） |
| task-mgmt 清理 | window-all-closed 时清理 | 模块级状态的生命周期与 app 生命周期一致 | 每次任务后清理（task 状态需要跨 turn 保留） |
