## 模块职责

### TrayManager (`src/main/tray/TrayManager.ts`) — 新建

托盘图标全生命周期管理器。单例，应用启动时创建，退出时销毁。

**职责：**
- 创建 Electron `Tray` 实例（各平台图标尺寸适配）
- 构建右键/左键上下文菜单（含动态对话列表子菜单）
- 处理托盘点击事件：左键（macOS 菜单 / Win+Linux 切换窗口）、双击（恢复窗口）、右键（菜单）
- 管理所有窗口的显示/隐藏：`showAllWindows()` / `hideAllWindows()`
- 检测 Linux 托盘可用性（`tray.isDestroyed()` 或创建后无响应）
- 首次最小化时发送 OS 原生通知
- 退出确认：查询活跃任务数 → 弹对话框 → `app.quit()`

**关键接口：**
```typescript
class TrayManager {
  create(): void                          // 创建托盘图标 + 初始菜单
  destroy(): void                         // 销毁托盘图标（退出时）
  refreshMenu(): void                     // 重建菜单（刷新对话列表）
  showAllWindows(): void                  // 恢复所有已隐藏窗口
  hideAllWindows(): void                  // 隐藏所有窗口到托盘
  isTrayAvailable(): boolean              // 托盘是否可用（Linux 降级检测）
  handleClose(win: BrowserWindow): void   // 窗口关闭拦截入口
}
```

### AutoLauncher (`src/main/tray/AutoLauncher.ts`) — 新建

跨平台开机自启管理。工厂模式，平台差异内部分支。

**职责：**
- 启用/禁用开机自启
- 查询当前自启状态
- 启动时判断是否为自启启动（用于静默启动逻辑）

**关键接口：**
```typescript
class AutoLauncher {
  enable(): Promise<void>          // 注册开机自启
  disable(): Promise<void>         // 注销开机自启
  isEnabled(): Promise<boolean>    // 查询自启状态
  wasAutoStarted(): boolean        // 本次启动是否来自自启（用于静默启动）
}
```

**平台实现差异：**
| 平台 | 机制 | 路径 |
|------|------|------|
| macOS | LaunchAgent plist | `~/Library/LaunchAgents/com.attago.attaseek.plist` |
| Windows | 注册表 Run key | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` |
| Linux | autostart .desktop | `~/.config/autostart/attaseek.desktop` |

### TraySettings (`src/main/tray/TraySettings.ts`) — 新建

interface TrayConfig {

### index.ts 修改点

窗口生命周期适配：

```typescript
// 现有行为：window-all-closed → 非 macOS 直接 quit
// 改为：window-all-closed → 根据 trayAvailable && minimizeToTray 决定是否 quit
app.on('window-all-closed', () => {
  if (!trayManager.isTrayAvailable() || !trayManager.isMinimizeToTrayEnabled()) {
    app.quit()
  }
  // 否则：窗口没了但托盘还在，不退出
})

// 窗口 close 事件：
// 现有行为：什么都不拦截，正常关闭
// 改为：最后一个可见窗口关闭时，若 minimizeToTray && trayAvailable，hide 而非 close
win.on('close', (e) => {
  if (trayManager.shouldMinimizeToTray(win)) {
    e.preventDefault()
    win.hide()
    // 首次最小化提示
  }
})
```

## 数据流

### 主流程 1: 关闭窗口 → 最小化到托盘

```
[用户点 ✕]
  → BrowserWindow 'close' 事件
  → TrayManager.handleClose(win)
    → 判断：是否为最后一个可见窗口？&& minimizeToTray 开启？&& 托盘可用？
      YES → e.preventDefault() + win.hide() + 首次则 OS 通知
      NO  → 允许正常关闭（非最后一个窗口直接关；或 Linux 降级模式直接退）
```

### 主流程 2: 托盘菜单"对话"子菜单

```
[用户右键托盘]
  → (菜单已在 create/refreshMenu 时预构建)
  → 对话子菜单项: { label: 标题, click: () => { showAllWindows(); pushNavigate(sessionId) } }
  → mainWindow.webContents.send('tray:navigate', { sessionId })
  → 渲染进程 App.tsx 监听 event → 路由跳转到指定 session
```

对话列表数据：`SessionStore.listSessions()` → 取最近 5 条 → 缓存到 `TrayManager.cachedSessions`。
刷新时机：托盘创建时、每次 `refreshMenu()` 调用时、`session:updated` 事件触发时。

### 主流程 3: 退出确认

```
[用户右键托盘 → 退出]
  → TrayManager.handleQuit()
  → agentRuntime.countActiveTasks() > 0 ?
    YES → dialog.showMessageBox({ type: 'warning', message: '有 N 个任务正在运行...', buttons: ['退出', '取消'] })
      → 用户选退出 → app.quit()
      → 用户取消 → 不做任何事
    NO  → app.quit()
```

### 主流程 4: 开机自启 → 静默启动

```
[OS 登录]
  → AutoLauncher 注册的入口启动 AttaSeek
  → main/index.ts: boot 完成后
  → if (autoLauncher.wasAutoStarted() && settings.startMinimized):
      → 创建所有窗口但不 show()（已有 ready-to-show 先 show 的逻辑需绕过）
      → 创建托盘图标
      → 主窗口保持隐藏
```

### 主流程 5: Linux 托盘降级

```
[应用启动]
  → TrayManager.create()
  → try: new Tray(icon)  // 可能不抛异常但托盘实际不工作
  → 检测: 短时间内托盘无交互响应 → 标记 trayAvailable = false
  → 设置:
      minimizeToTray 强制视为 false
      托盘设置项在渲染进程端隐藏 + 显示"当前桌面环境不支持系统托盘"
  → 窗口关闭行为回退为默认（关闭即退出）
```

## IPC Contract

| Channel | 方向 | 请求类型 | 响应类型 | 说明 |
|---------|------|---------|---------|------|
| `tray:navigate` | main→renderer (push) | — | `{ sessionId: string }` | 托盘菜单点击对话后的跳转指令 |
| `tray:get-settings` | renderer→main | — | `{ success: boolean; settings?: TrayConfig }` | 读取托盘设置 |
| `tray:set-settings` | renderer→main | `Partial<TrayConfig>` | `{ success: boolean }` | 更新托盘设置 |
| `tray:platform-info` | renderer→main | — | `{ trayAvailable: boolean; platform: string }` | 查询托盘可用性 + 平台（渲染进程据此决定是否显示设置项） |
| `tray:recent-sessions` | renderer→main | — | `{ sessions: { id: string; title: string }[] }` | 查询最近对话（备用，主进程可直接读 SessionStore） |
| `agent:active-task-count` | renderer→main | — | `{ count: number }` | 查询活跃（非终端状态）任务数 |

## Jotai Atoms（渲染进程）

| Atom | 类型 | 作用范围 | 持久化 | 说明 |
|------|------|---------|--------|------|
| `minimizeToTrayAtom` | `boolean` | 全局 | 是 (`attaseek-minimize-to-tray`) | 关闭窗口时最小化到托盘 |
| `autoLaunchAtom` | `boolean` | 全局 | 是 (`attaseek-auto-launch`) | 开机自动启动 |
| `startMinimizedAtom` | `boolean` | 全局 | 是 (`attaseek-start-minimized`) | 启动时最小化到托盘 |
| `trayAvailableAtom` | `boolean` | 全局 | 否 | 当前环境托盘是否可用（Linux 降级） |

> 设置变更后通过 `tray:set-settings` IPC 同步到主进程；主进程侧的设置权威源仍是 ConfigManager。

## Preload API 新增

```typescript
// src/preload/index.ts 中 api 对象新增 tray 命名空间
tray: {
  getSettings: (): Promise<{ success: boolean; settings?: TrayConfig }> =>
    ipcRenderer.invoke('tray:get-settings'),
  setSettings: (patch: Partial<TrayConfig>): Promise<{ success: boolean }> =>
    ipcRenderer.invoke('tray:set-settings', patch),
  getPlatformInfo: (): Promise<{ trayAvailable: boolean; platform: string }> =>
    ipcRenderer.invoke('tray:platform-info'),
  onNavigate: (cb: (data: { sessionId: string }) => void) => {
    const listener = (_e: IpcRendererEvent, data: { sessionId: string }) => cb(data)
    ipcRenderer.on('tray:navigate', listener)
    return () => ipcRenderer.removeListener('tray:navigate', listener)
  },
}
```

## 技术决策

| # | 决策 | 选择 | 理由 | 替代方案 |
|---|------|------|------|---------|
| 1 | 托盘菜单对话列表数据源 | 主进程直接读 SessionStore index（同步缓存），不通过 IPC 每次查询 | 菜单构建是同步 API，不能 await IPC；预缓存保证菜单瞬时弹出 | 用 `menu-will-show` 事件异步构建（仅 macOS 支持，跨平台不一致） |
| 2 | 窗口管理 | 不引入独立 WindowManager 模块；利用 Electron 内置 `BrowserWindow.getAllWindows()` + TrayManager 内聚显示/隐藏逻辑 | 当前只有单/少量窗口，新建模块是过度设计。TrayManager 作为托盘功能的门面，内聚窗口切换逻辑自然 | 新建 WindowManager 模块（若后续多窗口需求增长可重构，当前不必要） |
| 3 | Linux 托盘降级检测 | 创建 tray 后设 500ms 超时，若托盘对象无交互则标记不可用 | Electron 在无托盘支持的 Linux DE 上创建 Tray 不一定抛异常，但图标不显示且点击无响应。超时检测是务实的启发式方案 | 检测环境变量 `XDG_CURRENT_DESKTOP` + `GDMSESSION` 做桌面环境白名单（不完整且脆弱，GNOME+扩展的情况会误判） |
| 4 | 静默启动实现 | `app.on('ready')` 时判断 `wasAutoStarted()` 标志，设置 `startMinimized` 则不调用 `win.show()` | Electron 窗口创建和显示是分离的，`show: false` + `ready-to-show` 延迟 show 已有先例。自启标志通过启动参数 `--auto-started` 传递 | 启动后快速 hide()（有闪烁）、用 Electron `app.setLoginItemSettings()` 的 `openAsHidden`（跨平台兼容性差） |
| 5 | 设置持久化 | 复用 ConfigManager（`settings.json`），类型扩展 `TrayConfig`；渲染进程侧用 `atomWithStorage` 双写 localStorage | 与现有 30+ 设置项一致；两个持久化层（主进程 ConfigManager + 渲染进程 localStorage）是项目既有模式，保持统一 | 纯主进程设置（每次 IPC 读取延迟高，UI 响应慢） |
| 6 | 菜单对话列表更新策略 | 三个触发点：托盘创建时、`session:updated` IPC push 到达时、右键菜单弹出前（`menu-will-show` on macOS） | 覆盖"新对话""标题变更""切换到已有对话"三种场景。macOS 额外在弹出前刷新保证最新 | 定时轮询（耗资源）；只在创建时构建一次（过期） |

## 构建影响

- 图标资源需在 `resources/` 下新增托盘专用尺寸：
  - macOS: `tray-iconTemplate.png` (16×16, 模板图，自动适配 dark/light)
  - Windows: `tray-icon.ico` (16×16, 32×32)
  - Linux: `tray-icon.png` (22×22)
- electron-builder 配置：资源文件已在 `resources/` 打包范围内，无需修改

## 错误处理

| 场景 | 处理 |
|------|------|
| 托盘创建失败（Linux 降级） | `trayAvailable = false`，托盘功能整体禁用，设置 UI 展示说明 |
| AutoLauncher 注册失败 | 静默失败 + 日志记录 + UI 开关回弹（若注册失败，开关回到关闭并 toast 提示） |
| 会话列表读取失败 | 对话子菜单显示"加载失败"灰色提示，点击无操作 |
| 退出时窗口 destroy 卡住 | 2s 超时后 `app.exit()` 强制退出 |
| macOS 模板图标未找到 | 回退到应用图标缩放到 16×16 |
