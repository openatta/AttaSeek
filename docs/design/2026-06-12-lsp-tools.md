## 架构概览

```
┌── Main Process ──────────────────────────────────────┐
│                                                       │
│  Tool Implementations (lsp.ts)                        │
│    lsp_diagnostic / lsp_definition / lsp_references   │
│      │                                                │
│      ▼                                                │
│  LSPManager (singleton)                               │
│    ├── config: Map<languageId, LSPConfig>             │
│    ├── clients: Map<languageId, LSPClient>            │
│    ├── getClient(filePath) → LSPClient                │
│    ├── getDiagnostics(filePath) → Diagnostic[]        │
│    ├── getDefinition(filePath, line, char) → Location[]│
│    └── getReferences(filePath, line, char) → Location[]│
│      │                                                │
│      ▼                                                │
│  LSPClient (per language, one-to-one)                 │
│    ├── child_process (language server)                │
│    ├── JSON-RPC 2.0 over stdio                        │
│    ├── request queue (sequential, per-client)         │
│    ├── notification handler (diagnostics push)        │
│    └── lifecycle (init → ready → shutdown)            │
│                                                       │
└───────────────────────────────────────────────────────┘
```

## 核心类型

```typescript
// src/main/lsp/types.ts

/** 一个语言服务器的配置 */
export interface LSPConfig {
  languageId: string                        // e.g., 'typescript', 'rust'
  extensions: string[]                      // e.g., ['.ts', '.tsx']
  command: string                           // e.g., 'typescript-language-server'
  args: string[]                            // e.g., ['--stdio']
  env?: Record<string, string>
  initializationOptions?: Record<string, unknown>
  /** 服务器启动超时 ms，默认 30000 */
  startupTimeoutMs?: number
  /** 请求超时 ms，默认 10000 */
  requestTimeoutMs?: number
  /** 是否启用，默认 true */
  enabled?: boolean
}

/** LSP 诊断严重级别 */
export type DiagnosticSeverity = 1 | 2 | 3 | 4  // Error, Warning, Info, Hint

export interface LSPDiagnostic {
  range: {
    start: { line: number; character: number }
    end: { line: number; character: number }
  }
  severity: DiagnosticSeverity
  code?: string | number
  source?: string
  message: string
  relatedInformation?: Array<{
    location: LSPLocation
    message: string
  }>
}

export interface LSPLocation {
  uri: string
  range: {
    start: { line: number; character: number }
    end: { line: number; character: number }
  }
}

/** 客户端状态 */
export type LSPClientState = 'idle' | 'starting' | 'ready' | 'error' | 'shutting_down'
```

## LSPClient

### JSON-RPC 实现

使用 Node.js 内置能力，零外部依赖：

```
通信格式：
  → 写入 stdin:  Content-Length: <N>\r\n\r\n{jsonrpc body}
  ← 从 stdout 读取: 同上格式（LSP 标准 header+body 协议）

JSON-RPC 2.0:
  Request:  { jsonrpc: "2.0", id: number, method: string, params: object }
  Response: { jsonrpc: "2.0", id: number, result?: any, error?: { code, message } }
  Notification: { jsonrpc: "2.0", method: string, params: object }  // 无 id
```

### 连接建立流程

```
start(config)
  1. child_process.spawn(command, args, { stdio: ['pipe', 'pipe', 'pipe'] })
  2. 设置 stdout data handler → 解析 Content-Length header + JSON body
  3. 发送 initialize request:
     {
       method: 'initialize',
       params: {
         processId: process.pid,
         rootUri: workspaceRootUri,
         capabilities: {
           textDocument: {
             diagnostic: { dynamicRegistration: true },
             definition: { dynamicRegistration: true },
             references: { dynamicRegistration: true },
           }
         },
         initializationOptions: config.initializationOptions,
       }
     }
  4. 等待 initialize result（超时 startupTimeoutMs）
  5. 发送 initialized notification
  6. 状态 → 'ready'
```

### 文件生命周期

```
用户打开文件或 Agent 调 LSP 工具
  → LSPManager.getClient(filePath)
    → 已有同语言 client → 复用
    → 没有 → 创建新 LSPClient → start(config)

工具调用时:
  → client.ensureDocumentOpened(filePath)
    → 检查是否已发送 textDocument/didOpen
    → 没有 → 读文件内容 → 发送 didOpen notification
    → 有 → 如果文件内容变化 → 发送 didChange notification

  → client.sendRequest('textDocument/diagnostic', {
      textDocument: { uri: filePathToUri(filePath) }
    })
  → 返回 Diagnostic[]

关闭文件（闲置超时 5 分钟后）:
  → 发送 textDocument/didClose notification
  → 如果该 client 没有打开的文件 → 可选 shutdown 以释放资源
```

### 请求队列

```
每个 LSPClient 维护一个串行请求队列：
  - LSP 协议要求同一连接上的请求按序处理
  - sendRequest() 返回 Promise，内部排队
  - 超时保护：每个请求 requestTimeoutMs
  - 超时后 reject Promise，不中断队列（继续处理下一个）
```

### 错误处理

```
crash:
  → on('exit') → 状态 → 'error'
  → 所有 pending 请求 reject with 'Language server exited'
  → LSPManager 记录 crash 时间
  → 下次请求时自动重启（冷却时间 5s 内不重复重启）

startup timeout:
  → kill 进程
  → 状态 → 'error'
  → 返回友好错误消息（不含技术细节）

request timeout:
  → 该单个请求 reject
  → 连接保持，队列继续
  → 连续 3 次超时 → 标记连接为 degraded → 下次请求时重启
```

## LSPManager

```typescript
class LSPManager {
  private configs: Map<string, LSPConfig>   // languageId → config
  private clients: Map<string, LSPClient>   // languageId → client
  private degradedUntil: Map<string, number> // languageId → timestamp

  /** 加载配置（默认内置 + 用户自定义） */
  async loadConfigs(): Promise<void>

  /** 为给定文件获取或创建 LSP 客户端 */
  async getClient(filePath: string): Promise<LSPClient | null>

  /** 获取文件诊断 */
  async getDiagnostics(filePath: string): Promise<string>

  /** 跳转到定义 */
  async getDefinition(filePath: string, line: number, character: number): Promise<string>

  /** 查找引用 */
  async getReferences(filePath: string, line: number, character: number): Promise<string>

  /** 关闭所有语言服务器 */
  async shutdownAll(): Promise<void>
}
```

### 文件扩展名 → 语言 ID 解析

```
getLanguageId(filePath):
  ext = path.extname(filePath)
  for each config in configs:
    if ext in config.extensions → return config.languageId
  return null  // 无配置 → 降级
```

### 降级三层

| 层级 | 条件 | LSP 工具返回 |
|------|------|-------------|
| L1 就绪 | LSP server 启动成功 | 正常返回诊断/定义/引用结果 |
| L2 未安装 | `child_process.spawn` 抛出 ENOENT | `"Language server '{command}' not found. Install it to enable LSP support for {language}. Example: npm install -g typescript-language-server"` |
| L3 无配置 | 文件扩展名无匹配配置 | `"No language server configured for {extension} files. Add one in Settings → LSP."` |
| L3b 禁用 | 配置的 `enabled: false` | `"LSP is disabled for {language}. Enable it in Settings → LSP."` |

**设计决策：不自动下载语言服务器。** 这是工具类应用的惯例——让用户按需通过系统包管理器安装，避免：
- 包体积膨胀（一个 rust-analyzer 可能 30MB+）
- 许可证合规风险
- 版本管理复杂度

## 风险点

| 风险 | 缓解 |
|------|------|
| 语言服务器进程僵尸 | `LSPClient.shutdown()` 5s 超时后 SIGKILL；`LSPManager.shutdownAll()` 在 app quit 时调用 |
| 大项目初始化慢 (TS 10s+) | initialize 设置 30s 超时；初始化期间工具调用返回 "Language server initializing, retry in a moment" |
| 语言服务器 crash 循环 | crash 冷却时间 5s；连续 crash 3 次后标记为 degraded，10 分钟内不自动重启 |
| stdin/stdout 协议解析错误 | 严格按 Content-Length header 读取；buffer 中不完整帧留在内存等后续数据 |
| 并发请求排序 | 每个 LSPClient 内部队列串行化；不同语言的 client 之间完全独立 |
