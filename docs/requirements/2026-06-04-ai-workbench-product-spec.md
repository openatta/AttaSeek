## 1. 概述

### 1.1 目标

将 AttaSeek 定义为面向企业知识工作者的 AI 桌面工作台：用户提出目标后，系统自动组织上下文、调用工具、执行 Skill、生成可编辑 Artifact，并在权限可控和过程可追踪的前提下推进工作流。

一句话定位：

> Chat 是入口，Artifact 是结果，Skill 是能力，Memory 是连续性，Workflow 是壁垒。

### 1.2 背景

报告结论指出，AttaSeek 不应定位为"DeepSeek 桌面客户端"或普通 Chat 工具。通用聊天窗口、文件上传、Prompt 模板和少量工具调用的产品价值较薄，且会直接面对 ChatGPT、Claude、Codex、Cursor 等巨头产品的模型能力、生态和用户心智优势。

AttaSeek 的机会在于企业生产力工作流：

- 本地部署 / 私有化
- 中文办公和企业流程适配
- 企业内部系统深度集成
- 文档、邮件、IM、代码、知识库和任务系统之间的闭环
- 可控权限、操作预览、审计日志和回滚
- 将 AI 输出变成可编辑、可追踪、可复用的正式产物

### 1.3 产品原则

| 原则 | 说明 |
|------|------|
| 任务优先 | 用户不是来聊天，而是来完成文档、邮件、任务、代码、汇报等工作 |
| Artifact 优先 | 重要输出必须落为可编辑产物，不停留在纯文本回答 |
| 上下文自动化 | 用户只描述目标，系统主动查找相关项目、文档、邮件、知识和任务状态 |
| 人在回路中 | 高风险动作默认需要用户确认，第一版不追求全自动 |
| 记忆可见 | 记忆必须可查看、可编辑、可删除，避免黑盒用户画像 |
| 企业可控 | 权限分级、审计、私有化和数据边界从第一天纳入产品约束 |

### 1.4 用户角色

| 角色 | 说明 |
|------|------|
| 知识工作者 | 使用 AttaSeek 处理文档、邮件、资料、任务和项目推进 |
| 技术/产品人员 | 使用 AttaSeek 从需求、文档、代码、测试到汇报形成项目闭环 |
| 团队负责人 | 关注项目记忆、任务状态、团队模板、审计和权限控制 |
| 企业管理员 | 配置模型、插件、知识库、权限策略、审计和私有部署 |

## 2. 产品定义

### 2.1 AttaSeek 是什么

AttaSeek 是一个企业 AI 桌面工作台。它把 Chat、Artifact、Skills、Memory、Workflow 和权限系统组织在同一个桌面 Shell 中，让用户从"提出目标"到"生成可交付产物"形成闭环。

```text
输入：一句目标 / 一封邮件 / 一份文档 / 一个项目
处理：自动检索上下文 + 调用工具 + 执行技能 + 用户确认
输出：文档、邮件草稿、脑图、任务列表、代码变更、项目汇报
```

### 2.2 AttaSeek 不是什么

- 不是 DeepSeek 桌面客户端
- 不是只接一个模型 API 的聊天窗口
- 不是完整 IDE 的替代品
- 不是第一版就全自动操作企业系统的 RPA 工具
- 不是黑盒个人记忆或无审计 Agent

### 2.3 核心差异化

| 普通 Chat | AttaSeek AI 工作台 |
|---|---|
| 用户问，模型答 | 用户给目标，系统组织上下文并推进任务 |
| 输出为纯文本 | 输出为文档、草稿、脑图、任务、Diff 等 Artifact |
| 用户手动补上下文 | 系统自动检索项目、知识库、文件、邮件和任务状态 |
| 会话结束即断裂 | 项目记忆、偏好记忆、任务状态跨会话延续 |
| 工具调用弱约束 | 工具按风险分级，支持确认、预览、回滚和审计 |
| 通用场景 | 面向企业流程、模板、私有化和本地数据边界 |

## 3. 功能范围

### 3.1 MVP In Scope（第一版做）

#### A. 基础工作台 Shell

- Activity Bar + Sidebar + Conversation + Artifact 的多面板工作台
- 项目空间，项目作为文档、记忆、任务和上下文的容器
- Chat 作为任务入口，而不是唯一主面板

#### B. 文档工作台

- 导入 / 读取 Markdown、Word、PDF、LaTeX
- 文档总结、改写、正式报告生成、会议纪要生成
- 聊天结果可落为结构化文档 Artifact
- 支持局部编辑指令，例如"只修改第 4 到 14 章，前 3 章不动"
- 支持企业模板、章节结构和版本对比

#### C. 邮件工作台（监督式）

- 邮件导入、摘要、分类、提取待办
- 根据上下文起草回复
- 邮件转任务、邮件讨论转决策记录
- 回复发送前必须用户确认

#### D. 项目知识库与上下文

- 本地文件 / 文档索引
- 项目内知识问答
- 从问答进一步生成正式产物
- 支持"基于项目资料生成需求说明 / 技术方案 / 项目日报"

#### E. Artifact Workspace

- 支持文档、脑图、任务列表、代码 Diff、邮件草稿等可编辑产物类型
- Artifact 可继续被用户用自然语言局部修改
- 重要变更支持版本记录和对比

#### F. Skills 系统

- 原子技能：总结、改写、翻译、提取待办、分类邮件、生成文档、生成脑图、代码审查
- 场景技能：客户邮件处理、技术方案生成、会议纪要、产品规格书、PR review、项目日报
- 企业定制流程作为后续可视化编排的基础

#### G. 双层记忆

- 会话级临时记忆：当前任务上下文和中间结果
- 持久化语义记忆：用户偏好、项目决策、企业知识、任务状态
- 记忆必须可查看、可编辑、可删除

#### H. 权限与审计

- 工具权限三态：允许 / 每次确认 / 禁止
- 只读、可写、高风险工具分级
- 高风险动作必须展示操作预览并二次确认
- 所有工具调用、用户确认和结果落审计日志

#### I. 模型接入

- DeepSeek API 作为第一版重点接入对象
- 产品能力不绑定单一模型，保留 model-agnostic 抽象

### 3.2 Out of Scope（第一版不做）

- 自动发送邮件、自动发送 IM
- 自动修改企业生产系统
- 完整 IM 接管
- 完整 IDE 替代 Cursor / Codex / Claude Code
- 大规模多人实时协作
- 自动审批流
- 跨软件桌面操作 / Computer Use
- 完整企业私有化部署控制台

### 3.3 第二阶段范围

- 团队知识库
- 模板中心
- 项目记忆共享
- 任务看板
- IM 摘要和讨论转文档
- Gitea / GitHub / GitLab 接入
- 文档版本对比增强
- 团队级审计日志

### 3.4 第三阶段范围

- 私有化部署
- 内网模型接入
- LDAP / SSO
- 企业权限系统
- 企业插件市场
- 自定义流程编排
- 企业 API 网关
- 高风险操作审批

## 4. 核心工作流

### 4.1 文档处理闭环

```text
1. 用户选择项目或导入文档
2. 用户提出目标："根据这些资料生成客户需求说明"
3. 系统检索项目文件、历史资料、企业模板和相关记忆
4. Agent 给出计划，并说明将生成的 Artifact 类型
5. 系统生成文档 Artifact
6. 用户继续提出局部修改："展开第 3 章，不要动其它章节"
7. 系统只修改指定区域
8. 用户查看版本对比并确认
```

成功标准：

- 产物是可编辑文档，不只是聊天文本
- 用户能指定局部范围
- 修改过程可追踪
- 可复用企业模板和项目记忆

### 4.2 邮件 + 任务闭环

```text
1. 用户进入邮件工作台
2. 系统展示今日重要邮件摘要和待处理项
3. 用户选择一封客户邮件
4. 系统自动查找客户历史、产品规格、项目状态和不可承诺事项
5. Agent 生成回复草稿和内部待办
6. 用户审阅草稿
7. 用户确认后，系统保存草稿或交给邮件客户端发送
8. 相关待办写入任务状态记忆
```

成功标准：

- 第一版只做草稿和确认，不自动发送
- 草稿必须引用上下文来源
- 待办必须能进入项目任务状态

### 4.3 项目工作流闭环

```text
1. 用户进入项目空间
2. 用户输入："根据这份需求生成技术方案并拆任务"
3. 系统读取需求文档、项目记忆、代码结构和历史决策
4. Agent 生成技术方案 Artifact
5. 用户确认方案后，系统生成任务列表
6. 用户选择任务进入开发协作
7. 系统辅助生成变更说明、测试建议和项目日报
```

成功标准：

- 项目不是普通文件夹，而是上下文、任务、记忆和产物的容器
- Coding 场景重点是企业项目闭环，不是完整 IDE

### 4.4 今日工作摘要

```text
1. 用户启动 AttaSeek
2. 首页展示今日摘要
3. 摘要包括重要邮件、客户问题、IM 待办、项目文档、PR/代码审查提醒
4. 用户点击任一条目进入对应工作流
```

成功标准：

- 摘要来自项目、邮件、任务和记忆，不是静态入口
- 每个摘要项都能直接进入可执行工作流

## 5. 信息架构

### 5.1 Activity Bar

第一版建议保留并扩展以下入口：

| 入口 | 说明 |
|------|------|
| 首页 | 今日摘要、活跃任务、快捷入口 |
| 新建 | 新会话、新项目、新文档、新流程 |
| Search | 跨会话、项目、文档、知识库搜索 |
| Chat | 会话列表，按项目和状态分组 |
| Projects | 项目空间、项目任务、文件和记忆 |
| Documents | 文档工作台 |
| Mail | 邮件摘要、草稿和待办 |
| Automation | 后台任务和流程，MVP 可先占位 |
| Plugins / Skills | 插件、MCP、技能和企业流程 |
| Settings | 模型、权限、记忆、审计、外观和集成配置 |

### 5.2 Main Canvas

默认布局：

```text
┌────────────┬────────────────────┬────────────────────┐
│ Sidebar    │ Conversation       │ Artifact Workspace │
│ 场景/项目栏 │ Chat / Agent 控制区 │ 文档/脑图/任务/Diff │
└────────────┴────────────────────┴────────────────────┘
```

要求：

- Conversation 是工作流入口和控制面板
- Artifact Workspace 是主要结果区
- Sidebar 内容随 Activity 切换
- 面板布局支持后续拖拽、分栏和工作流预设

### 5.3 Artifact 类型

| 类型 | 示例 |
|------|------|
| 文档 | 需求说明、技术方案、会议纪要、产品规格书、项目日报 |
| 邮件草稿 | 客户回复、跟进邮件、内部同步 |
| 脑图 | 文档大纲、需求结构、会议整理 |
| 任务列表 | 待办、负责人、状态、来源 |
| 代码相关 | Diff、PR review、测试建议、变更说明 |
| 表格 | 需求矩阵、风险清单、客户问题列表 |

## 6. 权限、安全与审计

### 6.1 工具风险分级

| 级别 | 示例 | 默认策略 |
|------|------|----------|
| 只读工具 | 搜索文档、读取邮件、读取日历、搜索知识库、读取代码 | 可按用户配置允许 |
| 可写工具 | 新建文档、修改草稿、创建任务、修改代码 | 默认每次确认或按会话确认 |
| 高风险工具 | 发送邮件、发送 IM、删除文件、推送代码、修改生产配置、审批流程 | 必须二次确认 |

### 6.2 权限三态

- 允许
- 每次确认
- 禁止

权限应支持按工具、按项目、按会话和按风险级别配置。

### 6.3 高风险操作要求

高风险操作执行前必须提供：

- 操作对象
- 操作内容预览
- 影响范围
- 可回滚性说明
- 用户确认入口

### 6.4 审计日志

审计日志至少记录：

- 工具调用时间
- 发起会话和项目
- 工具名称和风险级别
- 输入摘要和输出摘要
- 用户确认结果
- 是否产生 Artifact 或外部副作用

## 7. 记忆系统

### 7.1 记忆类型

| 类型 | 说明 |
|------|------|
| 用户偏好记忆 | 文档风格、报告结构、代码风格、常用表达 |
| 项目记忆 | 项目目标、当前版本、设计决策、客户约束、禁止修改范围 |
| 企业知识记忆 | 产品规格、内部流程、客户资料、过往方案、常用模板 |
| 任务状态记忆 | 文档改到哪里、邮件是否回复、任务是否确认、代码是否提交 |

### 7.2 记忆体验要求

- 用户能看到系统记住了什么
- 用户能编辑错误记忆
- 用户能删除敏感或过时记忆
- 用户能关闭特定项目或特定类型记忆
- Agent 在使用重要记忆时应能说明来源

## 8. Success Metrics

### 8.1 MVP 成功标准

- 用户每天愿意打开 AttaSeek 处理文档、邮件、资料和任务
- 文档处理闭环能稳定生成可编辑产物
- 邮件工作流能稳定生成可信草稿和待办
- 项目空间能承载上下文、记忆、任务和产物
- 所有高风险工具调用都经过确认并可审计

### 8.2 可量化指标

| 指标 | 目标方向 |
|------|----------|
| Artifact 生成率 | 用户会话中产生可编辑产物的比例提升 |
| Artifact 二次编辑率 | 用户继续修改产物，说明产物进入真实工作流 |
| 每日活跃任务数 | 用户每天通过 AttaSeek 推进的任务数量 |
| 上下文命中率 | 系统自动找到有用上下文的比例 |
| 高风险确认覆盖率 | 高风险操作必须 100% 进入确认流程 |
| 审计日志完整率 | 工具调用和确认行为必须完整记录 |

## 9. 风险

| 风险 | 说明 | 对策 |
|------|------|------|
| 场景过散 | 文档、邮件、IM、Coding 同时做容易都很浅 | MVP 聚焦文档、邮件、项目知识库 |
| 复刻 Chat | 若只做聊天窗口，缺少差异化 | Artifact 和 Workflow 作为核心交付 |
| 自动化不稳定 | Agent 全自动执行容易误操作 | 采用 supervised agent，关键动作用户确认 |
| 权限事故 | 邮件、IM、文件、代码都有高风险 | 权限分级、预览、二次确认、审计和回滚 |
| 记忆不可信 | 黑盒记忆会引发隐私和准确性问题 | 记忆可见、可编辑、可删除，并标注来源 |
| 巨头覆盖通用功能 | 通用聊天和通用工具会被快速追平 | 深耕企业流程、模板、私有化和本地系统集成 |

## 10. 后续交接

本产品 spec 完成后，建议进入以下文档阶段：

1. `design-architecture`：设计状态机内核、Artifact Workspace、ToolRouter、Memory、Permission、Audit 的模块边界。
2. `write-plan`：拆分 MVP 实施计划，优先落地文档工作台、邮件草稿、项目知识库和权限审计。
3. `test-driven-development`：对权限确认、记忆可见性、Artifact 局部编辑、工具审计建立测试用例。
