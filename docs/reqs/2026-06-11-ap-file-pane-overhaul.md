# AP 文件面板优化 需求规格

**目标：** 简化文件面板的 UI 布局，扩大文件类型支持范围，统一查看体验，收窄实例策略。
**背景：** 当前文件面板存在路径栏冗余、文件类型支持有限（基本只支持 .md）、预览/源码双模式切换增加认知负担、实例策略不统一。需要从布局、能力、模式、策略四个维度对齐 Codex/Claude Code Desktop 的文件面板体验。
**创建日期：** 2026-06-11

---

## 1. 范围

### 1.1 In Scope

- [ ] **移除路径栏，TAB 上移** — 去掉文件面板标题下方的文件路径输入框/面包屑区域，将打开文件的 TAB 栏移到该位置。右侧边栏展开/收缩按钮保留在原位。
- [ ] **扩大文本文件支持** — 支持所有常见编程语言文件（.ts、.tsx、.js、.jsx、.py、.go、.rs、.java、.c、.cpp、.h 等）、配置文件和数据格式（.json、.xml、.yaml、.toml、.ini、.env、.csv、.log 等）、以及所有已知文本文件类型。所有代码文件打开后均有语法高亮。
- [ ] **二进制文件 HEX 查看** — 对于无法作为文本打开的文件，提供十六进制查看模式。
- [ ] **取消预览/源代码双模式** — 移除文件打开后顶部的"预览 | 源代码"切换按钮。文件打开即直接渲染，只有一种查看模式。
- [ ] **统一查看器** — 文本文件（代码/配置/Markdown）用 Monaco Editor 渲染并语法高亮；图片文件（PNG/JPG/GIF/SVG/WebP）直接展示；PDF 文件内嵌渲染。都走同一个查看区域，不区分"预览"和"源"模式。
- [ ] **单实例策略** — 文件面板每个工作区最多一个实例（内部可有多个文件 TAB）。浏览器面板每个工作区最多一个实例。审查面板每个工作区最多一个实例。只有终端面板允许多实例（多个终端 TAB 同时存在）。

### 1.2 Out of Scope

- 文件编辑、保存功能（本次不改文件写入能力）
- PDF 标注 / 搜索
- 图片编辑 / 裁剪
- 视频 / 音频文件播放
- 拖拽排序 TAB
- TAB 右键菜单增强
- 文件面板会话持久化（关闭后恢复 TAB 状态）

### 1.3 前置依赖

| 依赖 | 说明 | 状态 |
|------|------|------|
| Monaco Editor | 语法高亮能力已存在于代码/Diff 面板 | 已有 |
| 文件读取 IPC (`fs:read-file`) | 读取文件内容 | 已有 |
| 文件信息 IPC (`fs:file-info`) | 判断文件类型和 MIME | 已有 |
| AP 面板 TAB 系统 | 单实例约束机制 | 已有（浏览器已实现单实例） |
| 内嵌 PDF 渲染 | 需 PDF.js 或 iframe 方案 | 需新增 |

## 2. 用户场景

### 场景 1：打开一个 TypeScript 文件

- **给定** 用户在项目上下文中，文件面板已打开
- **当** 用户在文件浏览器中点击 `src/utils.ts`
- **则** 文件面板顶部创建/激活一个内部 TAB（标签为 `utils.ts`），内容区域用 Monaco Editor 渲染文件内容，TypeScript 语法高亮生效。没有路径栏，没有预览/源码切换。

### 场景 2：同一个文件面板内打开多个文件

- **给定** 文件面板已有一个 TAB（`utils.ts`）
- **当** 用户点击 `src/api.ts`
- **则** 新增内部 TAB（`api.ts`）并激活。之前的 `utils.ts` TAB 保留（未关闭）。TAB 栏在标题下方横排显示。点击任意 TAB 切换查看内容。

### 场景 3：关闭文件 TAB

- **给定** 文件面板有 3 个打开的文件 TAB
- **当** 用户 hover 某个 TAB，出现 × 图标，点击 ×
- **则** 该 TAB 关闭。如果关闭的是当前激活的 TAB，自动激活相邻 TAB。如果是最后一个 TAB 被关闭，显示空状态。

### 场景 4：打开一个图片文件

- **给定** 用户在文件浏览器中点击 `screenshot.png`
- **则** 文件面板新 TAB（`screenshot.png`），内容区域直接展示图片。无 Monaco Editor，无语法高亮。支持 PNG/JPG/GIF/SVG/WebP 格式。

### 场景 5：打开一个 PDF 文件

- **给定** 用户在文件浏览器中点击 `design-doc.pdf`
- **则** 文件面板新 TAB（`design-doc.pdf`），内容区域内嵌渲染 PDF。第一页可见，可滚动翻页。

### 场景 6：打开一个二进制文件（无可识别文本）

- **给定** 用户在文件浏览器中点击 `data.bin`
- **则** 文件面板新 TAB（`data.bin`），内容区域以 HEX 模式显示文件内容。左侧显示偏移量，中间显示十六进制值，右侧显示可打印 ASCII 字符。

### 场景 7：重复打开同一文件

- **给定** 文件面板已有一个 TAB（`utils.ts`）显示 `/src/utils.ts`
- **当** 用户再次点击文件浏览器中的 `utils.ts`
- **则** 不创建新 TAB，直接激活已有的 `utils.ts` TAB（焦点切换到该 TAB）。

### 场景 8：文件面板单实例约束

- **给定** 文件面板已打开
- **当** 用户点击 AP 的"文件"大按钮或 [+] 菜单中的"文件"
- **则** 不创建第二个文件面板实例，直接激活已存在的文件面板。

### 场景 9：超过可视区域的文件 TAB

- **给定** 文件面板内打开 10+ 个文件，TAB 栏空间不够
- **则** TAB 栏支持水平滚动（左右箭头）。当前激活的 TAB 保持在可视区域内。

### 场景 10：语法高亮的文件类型自动检测

- **给定** 用户打开一个没有标准扩展名的文本文件（如 `Dockerfile`、`Makefile`）
- **则** 系统根据文件名或内容特征自动推断语言，应用对应的语法高亮。如果无法推断，以纯文本模式显示。

### 场景 11：超大文件打开保护

- **给定** 用户尝试打开一个超过 10MB 的文本文件
- **则** 系统提示"文件过大，仅显示前 N KB"，截取文件前部内容显示。用户可选择"仍然打开全部"或"取消"。

### 场景 12：文件被外部修改

- **给定** 文件面板中 `config.json` 已打开
- **当** 外部程序修改并保存了该文件
- **则** 文件面板内容自动刷新，显示最新内容。TAB 标题不变。

## 3. 边界条件

| 条件 | 行为 |
|------|------|
| 空文件（0 字节） | 显示空白编辑区域 |
| 超长行（>10K 字符） | Monaco 自动折行 |
| 文件编码非 UTF-8 | 尝试检测编码（UTF-16/GBK/Latin-1），失败则显示乱码提示 |
| 同时打开 20+ 个文件 TAB | 允许，超出可视区滚动 |
| 文件已被删除（外部） | TAB 标题变灰/划掉，内容区显示"文件已被删除"，提供"关闭 TAB"按钮 |
| 文件面板关闭时内部 TAB 全部丢失 | 正确——不持久化（Out of scope） |

## 4. 布局变更说明

### 4.1 当前布局（变更前）

```
┌─ FilePane ─────────────────── [展开/收缩] ─┐
│ [路径输入框: /Users/xbits/MyApp/src/     ] │  ← 路径栏
│ ┌─ utils.ts ─┬─ api.ts ─┬─ + ────────────┐ │  ← 文件 TAB
│ │ 预览 | 源代码                            │ │  ← 模式切换
│ │                                         │ │
│ │ (文件内容)                               │ │
│ │                                         │ │
│ └─────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

### 4.2 目标布局（变更后）

```
┌─ FilePane ─── [utils.ts] [api.ts] [+] ── [☰] ─┐  ← TAB 上移，右侧边栏按钮保留
│                                                 │
│                                                 │
│              (文件内容 — 统一查看模式)            │
│       代码语法高亮 / 图片渲染 / PDF 内嵌          │
│                                                 │
│                                                 │
└─────────────────────────────────────────────────┘
```

**变更要点：**
1. 路径输入框/面包屑 **移除**
2. 文件 TAB 栏 **上移** 到标题行位置
3. "预览 | 源代码" 切换 **移除**
4. 右侧边栏展开/收缩按钮 **保留**

## 5. 文件类型支持清单

### 5.1 编程语言（Monaco 语法高亮）

| 语言 | 扩展名 |
|------|--------|
| TypeScript/TSX | `.ts`, `.tsx` |
| JavaScript/JSX | `.js`, `.jsx`, `.mjs`, `.cjs` |
| Python | `.py`, `.pyw`, `.pyi` |
| Go | `.go` |
| Rust | `.rs` |
| Java | `.java`, `.class` (HEX) |
| C/C++ | `.c`, `.cpp`, `.cc`, `.cxx`, `.h`, `.hpp` |
| C# | `.cs` |
| Swift | `.swift` |
| Kotlin | `.kt`, `.kts` |
| Ruby | `.rb` |
| PHP | `.php` |
| Shell | `.sh`, `.bash`, `.zsh`, `.fish` |
| SQL | `.sql` |
| Dart | `.dart` |
| Lua | `.lua` |
| R | `.r`, `.R` |

### 5.2 配置 / 数据格式

| 格式 | 扩展名 |
|------|--------|
| JSON | `.json`, `.jsonc` |
| YAML | `.yaml`, `.yml` |
| TOML | `.toml` |
| XML | `.xml`, `.svg` |
| INI/ENV | `.ini`, `.cfg`, `.env`, `.env.*` |
| CSV | `.csv` |
| Markdown | `.md`, `.mdx` |
| HTML/CSS | `.html`, `.htm`, `.css`, `.scss`, `.less` |

### 5.3 图片

PNG / JPG / JPEG / GIF / SVG / WebP / BMP / ICO

### 5.4 其他

| 类型 | 扩展名 | 渲染方式 |
|------|--------|---------|
| PDF | `.pdf` | 内嵌渲染（PDF.js / iframe） |
| 纯文本 | `.txt`, `.log`, `.diff`, `.patch` | Monaco（无语法高亮） |
| 无扩展名文本 | `Dockerfile`, `Makefile`, `LICENSE` 等 | Monaco（自动推断语言） |
| 二进制/未知 | 所有不匹配上述的 | HEX 查看 |

### 5.5 不支持（Out of scope）

- Office 文档（.docx, .xlsx, .pptx）
- 压缩包（.zip, .tar.gz）
- 视频/音频
- 可执行文件（.exe, .dylib）— HEX 查看可读但不特别处理

## 7. 风险

- **语法高亮覆盖不全** — Monaco 内置支持的语言约 60 种，但 Dart/Lua 等需要加载对应的 language worker。如果漏配，文件会以纯文本打开，用户困惑"不是说支持吗"。
- **HEX 查看体验预期差异** — 用户说的"HEX 查看"可能是想看二进制结构（如 ELF header），也可能只是想看文件有没有内容。需求文档无法精确到"HEX 视图应该长什么样"，架构设计阶段需要明确组件选择。
- **PDF 渲染依赖** — 需要 PDF.js 或浏览器内嵌 iframe。PDF.js 是额外依赖（~2MB），iframe 方案（用 Chrome 内置 PDF viewer）需要 CSP 放行 `file://` 或 `blob://` 协议。如果 CSP 策略不允许，需要改 Electron 配置。
- **大文件性能** — Monaco Editor 对 10MB+ 文件可能卡顿（行号计算、token 化）。需要虚拟滚动和分块加载策略。如果用户打开了 50MB 的日志文件，不加保护会导致界面冻结。
- **单实例策略与用户习惯冲突** — 有些用户可能习惯同时打开两个文件面板对照看代码。这个需求明确禁止了，但如果后续用户反馈强烈，需要重新评估。
- **SVG 渲染安全性** — SVG 支持 `<script>` 标签，如果直接 innerHTML 渲染 SVG 内容，存在 XSS 风险。需要用 `<img>` 标签或 sandbox iframe 渲染。
