# 系统托盘图标 需求规格

**目标：** 为 AttaSeek 提供系统托盘图标，支持关闭窗口时最小化到托盘保持后台运行、托盘快捷操作、开机自启静默启动。
**背景：** AttaSeek 作为 Agent 工作台，用户在发起长时间任务（代码生成、测试运行、部署）后希望关闭窗口让任务继续跑，而非被迫保持窗口打开。Codex Desktop 的托盘方案是这一体验的基准参考——关闭即最小化、托盘图标持续指示运行状态、右键快捷操作。

## 范围

- In scope:
  - **托盘图标**：应用启动后在系统托盘 / 菜单栏显示图标，所有窗口关闭且应用退出时移除
  - **关闭即最小化**：点击最后一个可见窗口的关闭按钮（✕）时隐藏窗口到托盘，应用不退出，Agent 任务继续运行
  - **多窗口支持**：多窗口场景按桌面应用惯例——关闭非最后一个窗口仅关闭该窗口；关闭最后一个窗口最小化到托盘；托盘"显示窗口"恢复所有窗口
  - **托盘交互**：左键按平台惯例（macOS 下拉菜单 / Windows & Linux 切换所有窗口显示隐藏）；右键上下文菜单
  - **右键菜单项**：显示/隐藏窗口、新建对话、最近对话列表（子菜单，最多 5 条，点击打开窗口并跳转到对应对话）、退出应用
  - **开机自启 + 静默启动**：支持配置"开机自动启动"，启动时直接最小化到托盘（不弹出窗口）
  - **退出确认**：在 Agent 任务运行中时，通过托盘菜单退出需确认"有 N 个任务正在运行，退出将中断它们"
  - **平台适配**：macOS 菜单栏（status bar app）、Windows 系统托盘（notification area）、Linux 系统托盘；各自遵循平台交互惯例
  - **Linux 托盘降级**：检测到系统托盘不可用时（如 vanilla GNOME），关闭按钮回退为退出应用，设置中隐藏托盘相关选项并附说明
- Out of scope:
  - 托盘图标状态指示（旋转/变色/badge）—— 本次使用静态图标
  - 通知推送（OS 原生通知由独立通知系统处理，不通过托盘触发）
  - 通过托盘直接查看/回复对话（本次只做导航跳转，不做迷你对话面板）
  - 从托盘菜单关闭/管理单个窗口（菜单操作面向整个应用，非单窗口）
- 前置依赖:
  - 应用图标资源（各平台所需尺寸）
  - Electron Tray API（Electron 内置能力，无外部依赖）
  - 最近对话列表数据（依赖已有会话存储，纯读取）
  - 多窗口管理能力（需主进程维护窗口列表）

## 用户场景

### 场景 1: 关闭最后一个窗口 → 最小化到托盘

- 给定: 用户使用 AttaSeek，Agent 正在执行一次代码生成任务，当前仅有 1 个窗口
- 当: 用户点击窗口关闭按钮（✕）
- 则:
  1. 窗口隐藏（不销毁）
  2. 托盘图标持续显示（若启动时已在托盘则保持不变）
  3. Agent 任务在后台继续执行，不受影响
  4. 任务完成后如有通知，通过 OS 原生通知提醒用户
  5. 用户点击托盘图标，窗口恢复显示，对话状态完整保留

### 场景 2: 多窗口下的关闭行为

- 给定: 用户打开了 3 个 AttaSeek 窗口（A 主窗口 + B 侧边对话 + C 侧边对话），Agent 任务在窗口 A 中运行
- 当: 用户依次关闭窗口 B、窗口 C
- 则:
  - 关闭 B → 窗口 B 正常关闭（非最后一个窗口，直接关闭）
  - 关闭 C → 窗口 C 正常关闭
  - 此时仅剩窗口 A，托盘图标始终显示
- 当: 用户接着关闭窗口 A（最后一个可见窗口）
- 则: 窗口 A 隐藏到托盘，应用不退出，Agent 任务继续运行

### 场景 3: 多窗口恢复

- 给定: 3 个窗口全部隐藏到托盘
- 当: 用户左键点击托盘图标（Windows/Linux）或通过托盘菜单选择"显示窗口"
- 则: 所有 3 个窗口恢复显示，Z-order 与隐藏前一致，最后聚焦的窗口获得焦点

### 场景 4: 托盘左键交互（按平台惯例）

- 给定: 应用有窗口隐藏于托盘
- 当: 用户左键点击托盘图标
- 则:
  - macOS: 弹出菜单（与右键菜单相同）
  - Windows / Linux: 切换所有窗口显示/隐藏
- 注: macOS 菜单栏应用左键即菜单是平台惯例，Windows/Linux 系统托盘左键切换窗口也是惯例，不统一

### 场景 5: 右键上下文菜单

- 给定: 应用正在运行（窗口可能显示或隐藏）
- 当: 用户右键点击托盘图标
- 则: 弹出上下文菜单，包含（按顺序）：
  1. **显示/隐藏窗口** — 根据当前是否有可见窗口动态切换文案；点击后切换所有窗口可见性
  2. **新建对话** — 加速键提示 `Cmd+N` / `Ctrl+N`；点击后确保至少一个主窗口可见并创建新对话
  3. **对话** — 子菜单，展开显示最近对话列表（最多 5 条）；每条显示对话标题（截断至 40 字符）；点击后确保窗口可见并跳转到对应对话
  4. **分隔线**
  5. **退出** — 点击后退出应用；若 Agent 有任务运行中则先弹出确认框

### 场景 6: 从托盘跳转到指定对话

- 给定: 用户有 5 条最近对话，所有窗口隐藏
- 当: 用户右键托盘 → 对话 → 选择"为 AttaSeek 写单元测试"
- 则:
  1. 窗口恢复显示并置前
  2. 自动导航到所选对话（在已有窗口中切换，或新建标签页承载）
  3. 对话列表菜单保持不变（不因选择而消失）

### 场景 7: 退出确认

- 给定: Agent 正在执行 2 个任务
- 当: 用户通过托盘菜单点击"退出"
- 则:
  1. 弹出确认对话框："有 2 个任务正在运行，退出将中断它们。确定退出吗？"
  2. 用户确认 → 正常退出流程（保存状态、释放资源、移除托盘图标）
  3. 用户取消 → 回到托盘，任务继续运行
- 当: 没有任务运行中
- 则: 直接退出，不弹确认框

### 场景 8: 开机自启 + 静默启动

- 给定: 用户在设置中开启了"开机自动启动"和"启动时最小化到托盘"
- 当: 用户登录操作系统
- 则:
  1. AttaSeek 自动启动
  2. 不弹出任何窗口（静默启动）
  3. 托盘图标出现，表示应用已在后台运行
  4. 用户需要时通过托盘图标打开窗口

### 场景 9: 双击托盘图标

- 给定: 所有窗口隐藏于托盘
- 当: 用户双击托盘图标
- 则: 在所有平台上均恢复所有窗口并置前（双击 = 明确意图要打开窗口，覆盖 macOS 左键行为差异）

### 场景 10: 无对话时菜单

- 给定: 用户首次使用 AttaSeek，尚无任何对话记录
- 当: 用户右键托盘图标
- 则: "对话"子菜单显示"暂无对话"，灰色不可点击

### 场景 11: 托盘不可用降级（Linux）

- 给定: 用户在 vanilla GNOME（无系统托盘支持）上运行 AttaSeek
- 当: 应用启动
- 则:
  1. 检测到托盘不可用，托盘图标不创建（不报错）
  2. 窗口关闭按钮行为回退为"退出应用"（关闭即退出，不可最小化到托盘）
  3. 设置 → 通用中，托盘相关三个配置项隐藏，并显示说明「当前桌面环境不支持系统托盘」
  4. 应用其他功能不受影响

### 场景 12: 应用退出时托盘清理

- 给定: 托盘图标正在显示
- 当: 应用通过任何方式退出（托盘菜单退出、主窗口 `Cmd+Q`、OS 关机信号）
- 则: 托盘图标立即移除，不留残留。图标即使因崩溃残留，鼠标悬停时也会消失（OS 行为保证）

### 场景 13: 设置项

- 给定: 用户打开设置面板
- 当: 用户进入"通用"设置区域
- 则: 可见以下托盘相关配置项：
  1. **关闭窗口时最小化到托盘** — 开关，默认**开启**
  2. **开机自动启动** — 开关，默认**关闭**
  3. **启动时最小化到托盘** — 开关，默认**关闭**；仅在"开机自动启动"开启时可用（否则灰色）
  4. **退出快捷键** — 信息展示行（`Cmd+Q` / `Ctrl+Q` 始终强制退出，不受"关闭即最小化"影响）

## 非功能需求

- **可靠性**：托盘图标必须与主进程生命周期严格绑定。托盘图标残留（进程已退出但图标仍在）是不可接受的 bug。
- **性能**：托盘菜单中"最近对话"列表从本地 SQLite 读取，查询耗时 < 50ms，不影响 UI 线程。
- **平台兼容性**：
  - macOS 14+（Apple Silicon + Intel）：菜单栏图标，左键弹出菜单
  - Windows 10/11：系统托盘（notification area），左键切换窗口
  - Linux：主流 DE（KDE、XFCE、GNOME+扩展）原生托盘支持；vanilla GNOME 优雅降级
- **可访问性**：托盘菜单项标注对应键盘加速键（如适用）。

## 风险

- **Linux 桌面环境碎片化**：系统托盘在各 DE 中支持度不一，GNOME 需用户自行安装扩展。降级方案（场景 11）已定义，但用户体验仍会割裂——需要在文档/首次启动中引导 GNOME 用户安装托盘扩展。
- **关闭即最小化用户习惯冲突**：部分用户期望点 ✕ 就是退出。默认开启可能导致困惑（"为什么关了还在跑？"）。**缓解措施**：首次最小化时用 OS 通知告知"AttaSeek 仍在后台运行，可通过托盘图标恢复窗口"（仅提示一次，记录到设置不再重复）。
- **开机自启的跨平台实现差异**：macOS（LaunchAgent plist）、Windows（注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`）、Linux（`~/.config/autostart/.desktop`）机制各不相同。macOS 可能触发"登录项"权限弹窗，需在设置中引导用户到系统设置授权。
- **退出确认时机**：判断"Agent 是否在运行任务"需要主进程提供可靠的任务状态查询接口。若状态不准确，可能导致误判——任务实际已死但显示为运行中，阻止用户退出。
- **多窗口 Z-order 恢复**：隐藏窗口再恢复后，OS 不保证 Z-order 与隐藏前一致。部分窗口管理器可能将恢复的窗口置于其他应用之后，需要显式 `focus()` 置前。
