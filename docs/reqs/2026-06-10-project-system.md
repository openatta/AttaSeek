# 项目系统 需求规格

**目标：** 让用户创建和管理项目，在项目上下文中进行 AI 辅助开发。会话统一存储在全局数据目录，通过项目元数据关联会话与项目路径。
**背景：** 当前仅有全局 CHATS 会话。开发者需要以项目为单位组织工作——每个项目绑定一个本地目录作为工作区，选中项目后 agent 自动获得该目录作为工作上下文。同时，项目上下文解锁 AP 面板的文件和审查 Pane。
**创建日期：** 2026-06-10 ｜ **最后修订：** 2026-06-10
**参考：** Codex Desktop（OpenAI）Projects 侧边栏实现

## 1. 概述

### 1.1 核心概念

| 概念 | 定义 |
|------|------|
| **项目（Project）** | 一个绑定到本地目录的工作区。全局存储记录 `{ id, name, rootPath }`。 |
| **项目会话** | 与 CHATS 会话结构完全相同（共用 session 类型），区别在于 `session` 记录中 `projectId` 非空。存储位置与 CHATS 会话相同（全局数据目录）。 |
| **项目上下文** | 当用户在左边栏选中某个项目时，整个应用进入该项目的工作上下文——agent 工作目录设为 rootPath；AP 面板的文件和审查 Pane 变为可用。 |
| **项目元数据** | 全局存储中记录：项目 ID、项目名称、rootPath、创建时间、关联的 session ID 列表。 |

### 1.2 与 CHATS 的关系

| | CHATS 会话 | 项目会话 |
|---|-----------|---------|
| 存储位置 | 全局数据目录 | **全局数据目录（与 CHATS 相同）** |
| sessionId | 全局 ID 空间 | **全局 ID 空间（共用）** |
| 区分方式 | `projectId = null` | `projectId = <项目ID>` |
| 工作目录 | 无（使用用户 Home） | 项目 rootPath |
| 会话可见性 | 按 Activity 归类 | 挂在左边栏对应项目下方 |
| AP Pane 可用性 | 浏览器 + 终端 | 全部 4 个（浏览器/终端/文件/审查） |
| 记忆可见性 | 全局记忆 | **项目记忆仅在项目上下文中可见，全局 CHATS 中不可见** |

## 2. 范围

### 2.1 In Scope

- [ ] **创建项目** — 弹窗表单：项目名称（必填）+ 项目目录（必填，目录选择器）。创建后在全局存储记录项目元数据。
- [ ] **项目左边栏** — PROJECTS 区域列出所有项目；每个项目下方缩进显示其会话列表（通过 projectId 过滤）
- [ ] **选中即激活** — 点击左边栏项目即进入该项目上下文（无需额外"打开"动作）
- [ ] **项目级会话创建** — 仅当有选中项目时，PROJECTS 标题旁的 [+] 按钮才可用；创建的会话自动设置 projectId 归属到选中项目
- [ ] **会话加载** — 点击项目下的会话，加载历史记录，展示方式与 CHATS 会话完全一致；agent 工作目录设为项目 rootPath
- [ ] **会话全局存储** — 项目会话与 CHATS 会话共用同一个全局 session store，通过 projectId 字段区分和过滤
- [ ] **项目记忆隔离** — 项目下的记忆在全局 CHATS 中不可见；filter by projectId
- [ ] **移除项目（含清理）** — 停止该项目下所有运行中的 agent 任务 → 从全局存储删除项目元数据和关联 session 记录 → 若项目目录仍存在，删除 `<rootPath>/.atta/seek/` 目录 → 若 `.atta/` 目录已空，一并删除 `.atta/`
- [ ] **项目上下文激活 AP Pane** — 选中项目后，AP 面板的文件和审查 Pane 变为可用（需要项目上下文）
- [ ] **项目空状态** — 无项目时 PROJECTS 区域显示引导提示；有项目但无会话时显示空会话状态
- [ ] **项目上下文指示器** — 界面某处明确显示当前活跃的项目名称

### 2.2 Out of Scope

- 项目级独立的模型配置 / agent 指令（后续扩展）
- 项目归档 / 导出 / 导入
- 同一目录被多次添加为不同项目（后续加校验）
- 项目拖拽排序
- 项目间会话迁移
- 多人协作项目
- 项目模板 / 脚手架

### 2.3 前置依赖

| 依赖 | 说明 | 状态 |
|------|------|------|
| 文件系统 IPC（`fs:*`） | 创建项目时验证目录存在、可读写；移除时清理 `.atta/seek/` | 已实现 |
| 项目根路径状态（`projectRootAtom`） | 选中项目时设置，控制 FilePane/ReviewPane 门控 | 已实现 |
| 会话系统 | session 记录需增加 `projectId` 字段；列出会话支持按 projectId 过滤 | 需扩展 |
| 记忆系统 | memory 记录需增加 `projectId` 字段；查询支持 projectId 范围 | 需扩展 |
| 左边栏 PROJECTS 区域 | 新的侧边栏视图，列出项目+会话树 | 需新建 |
| Agent 任务取消 | 移除项目时需停止关联的 agent 任务 | 需扩展 |

## 3. 用户场景

### 场景 1：创建第一个项目

- **给定** 用户首次使用项目功能，PROJECTS 区域为空
- **当** 用户点击 PROJECTS 旁的 [+] 或区域内的引导按钮
- **则** 弹出创建项目对话框：项目名称、目录选择器（打开系统文件选择器）、取消和创建按钮
- **当** 用户填写名称 "MyApp"、选择目录 `/Users/xbits/MyApp`、点击创建
- **则** 项目元数据 `{ id, name: "MyApp", rootPath: "/Users/xbits/MyApp" }` 写入全局存储；项目 "MyApp" 出现在左边栏并被自动选中

### 场景 2：选中项目激活上下文

- **给定** PROJECTS 区域有项目 "MyApp"
- **当** 用户点击 "MyApp"
- **则** "MyApp" 高亮；projectRootAtom = `/Users/xbits/MyApp`；AP 面板文件/审查 Pane 变为可用

### 场景 3：在项目下创建会话

- **给定** 项目 "MyApp" 已被选中
- **当** 用户点击 PROJECTS 旁的 [+]
- **则** 创建新 session，`projectId = "<项目ID>"`；会话显示在左边栏项目 "MyApp" 下方（缩进）
- **当** 用户点击该会话
- **则** 加载会话历史，agent 工作目录 = `/Users/xbits/MyApp`；对话渲染与 CHATS 一致

### 场景 4：项目会话历史加载

- **给定** 项目 "MyApp" 下有 3 条会话
- **当** 用户点击其中一条
- **则** 从全局 session store 加载（按 projectId + sessionId 查询），渲染与 CHATS 会话完全一致

### 场景 5：项目记忆隔离

- **给定** 用户在项目 "MyApp" 下产生了记忆 "API 端口是 8080"
- **当** 用户切换到 CHATS 视图并发起对话
- **则** agent 上下文中不包含项目 "MyApp" 的记忆（projectId 过滤）

### 场景 6：移除项目（完整清理）

- **给定** 项目 "MyApp" 存在于左边栏，其下有活跃 agent 任务
- **当** 用户右键点击项目名 → 选择"移除" → 确认
- **则** 1) 停止该项目下所有运行中的 agent 任务；2) 从全局存储删除项目元数据；3) 从全局存储删除 projectId 匹配的所有 session 记录；4) 检测 `<rootPath>/.atta/seek/` 是否存在 → 若存在则删除；5) 检测 `<rootPath>/.atta/` 是否为空 → 若为空则删除 `.atta/`；6) 项目从左边栏消失；若当前激活的是该项目，切换回全局 CHATS 上下文

### 场景 7：移除项目时目录已不存在

- **给定** 项目 "MyApp" 绑定到 `/Users/xbits/MyApp`，该目录已被外部删除
- **当** 用户移除项目
- **则** 仅执行全局数据清理（步骤 1-3），跳过文件系统清理（步骤 4-5）

### 场景 8：切换项目

- **给定** 项目 A 当前选中，项目 B 也存在
- **当** 用户点击项目 B
- **则** 项目 A 取消选中，项目 B 选中；projectRootAtom 更新为项目 B 的 rootPath；当前显示的会话保持不变直到用户选择项目 B 下的会话

### 场景 9：项目上下文与 CHATS 切换

- **给定** 用户在项目 "MyApp" 上下文中
- **当** 用户点击 ActivityBar 的 CHATS 图标
- **则** 切换回全局 CHATS 视图；projectRootAtom = null；AP 面板文件/审查 Pane 变为不可用

### 场景 10：异常 — 项目目录不存在

- **给定** 项目 "MyApp" 绑定到 `/Users/xbits/MyApp`，该目录已被外部删除
- **当** 用户点击该项目或尝试在其下创建会话
- **则** 提示"项目目录不存在"；提供"定位目录"和"移除项目"两个选项

### 场景 11：异常 — 项目目录无读写权限

- **给定** 项目绑定的目录缺少读或写权限
- **当** 用户尝试创建会话
- **则** 提示权限不足，无法创建会话

### 场景 12：异常 — 创建项目时目录不存在

- **给定** 用户在创建项目对话框中手动输入了一个不存在的路径
- **当** 用户点击创建
- **则** 提示"目录不存在，是否创建？"，确认后自动创建目录并继续

### 场景 13：边界 — 没有选中项目时 PROJECTS 的 [+]

- **给定** PROJECTS 区域有项目但无选中项目
- **当** 用户点击 PROJECTS 旁的 [+]
- **则** [+] 按钮禁用或不可见；提示"请先选中一个项目"

### 场景 14：边界 — 项目名称为空或纯空格

- **给定** 创建项目对话框已打开
- **当** 用户未输入名称或输入纯空格 → 点击创建
- **则** 创建按钮禁用；名称输入框显示验证提示

## 4. 左边栏 PROJECTS 区域布局

```
┌─ PROJECTS ──────────────────────── [+] ─┐
│                                           │
│  ● MyApp                      (选中高亮)  │
│     └─ 调试 API 接口                      │
│     └─ 重构用户模块                       │
│     └─ 修复登录 BUG                       │
│  ○ BackendService                         │
│  ○ Website                                │
│                                           │
│  [+ Add Project]               (引导按钮) │
└───────────────────────────────────────────┘
```

**行为：**
- ● 表示当前选中（激活上下文），○ 表示未选中
- 会话名称缩进显示在项目下方
- 会话列表始终可见（不折叠）
- 点击项目名称 → 选中并激活上下文
- 右键项目名称 → 弹出菜单（至少含"移除"）
- 无项目时显示引导："No projects yet."
- 项目有但无会话时显示："No sessions"

## 5. 创建项目对话框

```
┌─ 创建项目 ────────────────────────────────┐
│                                             │
│  项目名称 *                                  │
│  ┌─────────────────────────────────────┐    │
│  │ MyApp                               │    │
│  └─────────────────────────────────────┘    │
│                                             │
│  项目目录 *                                  │
│  ┌─────────────────────────────────────┐    │
│  │ /Users/xbits/MyApp          [选择]  │    │
│  └─────────────────────────────────────┘    │
│                                             │
│                    [取消]    [创建项目]      │
└─────────────────────────────────────────────┘
```

- 项目名称：文本输入，必填，trim 后长度 ≥ 1
- 项目目录：文本输入 + [选择] 按钮打开系统原生目录选择器；必填
- 创建按钮：两者都有效时才可用
- 创建成功后关闭对话框，项目出现在左边栏并自动选中

## 6. 数据模型

### 6.1 全局存储新增

```
projects 表（或 JSON 配置）
├── id: string              # 项目 ID
├── name: string            # 项目名称
├── rootPath: string        # 项目根目录（绝对路径）
├── createdAt: number       # 创建时间戳
└── sessionIds: string[]    # 关联的 session ID 列表

session 记录（现有类型扩展）
└── projectId: string | null   # null = CHATS 会话，非空 = 项目会话
```

### 6.2 数据生命周期

```
创建项目
  → 全局存储写入项目元数据（id, name, rootPath）
  → 项目出现在左边栏

创建项目会话
  → 全局存储写入 session（projectId = <项目ID>）
  → 会话出现在左边栏对应项目下方

选中项目
  → projectRootAtom = rootPath
  → agent 工作目录 = rootPath

移除项目
  → 停止该项目所有活跃 agent 任务
  → 全局存储：删除项目元数据
  → 全局存储：删除 projectId 匹配的所有 session 记录
  → 文件系统：若 rootPath 存在 → 删除 <rootPath>/.atta/seek/
  → 文件系统：若 <rootPath>/.atta/ 已空 → 删除 <rootPath>/.atta/
  → 项目从左边栏消失

切换到 CHATS
  → projectRootAtom = null
  → agent 工作目录 = 默认（用户 Home）
```

### 6.3 数据存储路由（全局统一）

| 数据类型 | 存储位置 | 过滤方式 |
|---------|---------|---------|
| 所有会话（CHATS + 项目） | 全局数据目录 | `projectId: null` → CHATS；`projectId: <ID>` → 项目 |
| 所有记忆 | 全局数据目录 | `projectId` 过滤——项目记忆仅项目上下文可见 |
| 审计日志 | 全局数据目录 | 同上 |
| 项目元数据 | 全局数据目录 | 项目注册表 |

## 8. 风险

- **路径变更** — 用户外部移动/重命名项目目录后，项目变"僵尸"。需健壮异常处理。
- **移除项目不可逆** — 删除全局 session 记录和 `.atta/seek/` 后无法恢复。需确认对话框明确告知后果。
- **agent 任务中断** — 移除项目时强制停止 agent 可能丢失进行中的工作。需在确认对话框中提示"有 N 个活跃任务将被停止"。
- **并行项目会话** — 项目 A 和项目 B 的 agent 同时运行，需确保工作目录、记忆、上下文完全隔离。
